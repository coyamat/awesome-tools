あなたはClaude Codeのカスタムスラッシュコマントを作成するエキスパートです。
ユーザーが行った一連の作業を分析し、再利用可能なカスタムスラッシュコマンドとして定式化してください。

## タスク

$ARGUMENTS

引数が空の場合は、現在の会話の中でユーザーが行った作業を分析し、カスタムスラッシュコマンドを作成してください。

## カスタムスラッシュコマンドの仕様

Claude Codeのカスタムスラッシュコマンドは以下のルールに従います：

- ファイルの場所:
  - プロジェクト単位: `.claude/commands/<command-name>.md`
  - ユーザー単位（全プロジェクト共通）: `~/.claude/commands/<command-name>.md`
- ファイル形式: Markdownファイル（`.md`）
- コマンド名: ファイル名がそのままスラッシュコマンド名になる（例: `fix-bug.md` → `/fix-bug`）
- 引数: `$ARGUMENTS` プレースホルダーを使ってユーザーからの引数を受け取れる
- 内容: Claudeへの指示をMarkdown形式で記述する

## 手順

1. **作業内容の分析**: ユーザーが行った作業・会話の内容を把握する
2. **コマンドの目的を定義**: その作業を汎用的に再現できるコマンドの目的を明確にする
3. **コマンド名を決定**: 作業内容を端的に表す英語の kebab-case 名前を決める
4. **プロンプトを設計**: 以下の要素を含む効果的なプロンプトを作成する
   - コンテキスト・背景説明
   - Claudeに期待する役割
   - 具体的な手順（ステップバイステップ）
   - 入力・出力の形式
   - `$ARGUMENTS` の使い方（必要な場合）
5. **ファイルを作成**: `.claude/commands/<command-name>.md` に書き出す

## 出力フォーマット

作成したコマンドについて以下を報告してください：

- **コマンド名**: `/command-name`
- **ファイルパス**: `.claude/commands/command-name.md`
- **用途**: このコマンドが何をするか1〜2文で説明
- **使用例**: 実際にどのように呼び出すか例示

## 注意点

- プロンプトは日本語で記述してOK（ユーザーの言語に合わせる）
- 汎用性を持たせる: 特定のファイル名やプロジェクト固有の情報はハードコードせず `$ARGUMENTS` で受け取る
- 明確な指示: Claudeが迷わないよう、具体的かつ明確な指示を書く
- 適切な粒度: 大きすぎず小さすぎないコマンドにする
